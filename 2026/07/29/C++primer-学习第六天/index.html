第10章 泛型算法
10.1 lambda表达式
1.基本语法：[capture list](parameter list)mutable->return type{function body}
捕获列表[]：访问所在函数的局部变量
捕获方式：1.值捕获[var]，拷贝变量到lambda内部，默认const，不加mutable不能修改。
2.引用捕获[&var]，绑定外部变量引用，lambda内修改会直接改变外部原值
3.全部捕获简写：[=]:全部值捕获。[&]:全部引用捕获
4.混合捕获示例:[=,&x]: 默认值捕获，唯独x引用捕获。[&,y]：默认引用捕获，唯独y值捕获
捕获时机：
lambda捕获发生在lambda被定义时，不是调用时。
int x = 10;
auto f = x{cout<<x;}
x = 100;
f(); //输出10，而不是100
mutable关键字作用
值捕获的副本默认是const，mutable唯一作用：去掉副本的const限制，允许在lambda内部修改拷贝出来的副本
返回类型推导规则
1.函数体内只有一条return语句：可以省略->type，编译器自动推导返回类型
2.多条return，分支返回不同类型：必须显式写尾置返回类型

10.2 bind函数
1.基础语法：auto new_callable = bind(origin_func,arg1,arg2,...,_placeholders::_1,_placeholders::_2);
         _1,_2,_3...：占位符，定义在std::placeholders，表示调用新函数时传入的第一个，第二个，第三个实参
2.bind参数传递规则：
         默认是值传递，如果想绑定引用，必须使用ref()/cref()
         void func(int& x)
         {
            int a=10;
            auto f=bind(func,ref(a));//传入引用
            //auto f=bind(func,a);   //会拷贝副本，传值
         }
3.bind 适用场景：
         需要参数重排，少量参数固定，兼容老式代码

第十一章 关联容器
11.1 分别给出最适合使用list,vector,deque,map以及set的例子
list:频繁在容器中间位置插入删除元素，几乎不需要随机访问
vector:大量随机访问，只在尾部增删元素，很少在中间插入删除
deque:需要随机访问，并且频繁在容器头部和尾部插入，删除元素
map:保存键—值映射关系，按键有序查找
set:保存不重复的元素，自动保持有序，快速查找元素是否存在

11.2 可以定义一个vector<int>::iterator到int的map吗？list<int>::iterator到int的map呢？对于两种情况，如果不能解释为什么
    map<vector<int>::iterator,int>:合法，vector迭代器支持<比较，满足map键的排序要求
    map<list<int>::iterator,int>:标准C++下不合法，list双向迭代器只提供==/!=,未定义<,map无法对键进行有序排序

11.3 关联容器操作
    key_type    此容器类型的关键字类型
    mapped_type 每个关键字关联的类型
    value_type  对于set，与key_type相同
                对于map,为pair<const key_type,mapped_type>
    如下面定义
    set<string>::value_type v1;        v1是一个string
    set<string>::key_type v2;          v2是一个string
    map<string,int>::value_type v3;    v3是一个pair<const string,int>
    map<string,int>::key_type v4;      v4是一个string
    map<string,int>::mapped_type v3    v5是一个int

11.4 对于什么问题你会选择count来解决，什么时候又会选择find呢
    1.使用count的场景：只需要知道某个键是否存在，一共有多少个匹配元素，不需要拿到元素迭代器
    count返回值：键出现的次数(0代表不存在，大于0代表存在)
    2.使用find的场景：需要定位到该元素，并对元素进行读取，修改，删除操作
    find返回迭代器：找到则返回元素迭代器，找不到返回尾后迭代器

11.5 upper_bound,lower_bound和equal_range
    1.upper_bound和lower_bound:
    这两个操作都接受一个关键字，返回一个迭代器。如果关键字在容器中，lower_bound返回的迭代器将指向第一个具有给定关键字的元素
    而upper_bound返回的迭代器则指向最后一个匹配给定关键字的元素之后的位置。如果元素不在multimap中，则返回相等的迭代器--指向
    一个不影响排序的关键字插入位置
    2.equal_range
    接受一个关键字，返回一个迭代器的pair。若关键字存在，则第一个迭代器指向第一个与关键字匹配的元素，第二个迭代器指向最后一个
    匹配元素之后的位置，若未找到匹配元素，则两个迭代器都指向关键字可以插入的位置

11.7 一个无序容器与其有序版本相比有何优势？有序版本有何优势
1.无序容器(unordered_map,unordered_set)优势：查找，插入，删除平均时间复杂度为O(1),速度更快
不需要维护元素有序，省去排序开销
2.有序容器(map,set)优势：元素始终按关键字有序排列，可以遍历得到有序序列
支持lower_bound,upper_bound,equal_range等范围查找操作
最坏性能稳定，操作复杂度为O(log n),不会出现哈希冲突导致性能暴跌
关键字只需支持<比较，不需要定义哈希函数
