第七章 类
7.1 默认构造函数是参数列表为空的构造函数
答案：这句话是错误的，以下两种情况都属于默认构造函数：
1.形参列表全部带默认实参(不一定是空的参数列表)
2.没有形参(参数列表为空)

7.2 关键字explicit只对一个实参的构造函数有效，需要多个实参的构造函数不能用于执行隐式转换
所以无需将这些构造函数声明为explicit，只能在类的声明构造函数时使用explicit关键字，在类的
外部定义时不能重复
Sales_data item1(null_book); //正确，直接初始化
Sales_data item2 = null_book; //错误：不能将explicit构造函数用于拷贝形式的初始化

7.3 vector将其单参数的构造函数定义成explicit的，而string不是，你觉得原因何在？
我的答案：vector定义成explicit，是防止里面的类型隐式转化为容器
而string不需要是因为，将char或者const char*类型转化为string类型是容器默认的行为

7.4 什么是类的静态成员？它有何优点？静态成员和普通成员有何区别
我的答案：类的静态成员与类的本身相关，而与类的对象无关，他存在于整个程序的声明周期
普通成员的生命周期随对象的生命周期的变化而变化。不是又不是清楚

第九章 顺序容器
9.1 为了读取string的list中的元素，应该使用什么类型？如果写入list，又该使用什么类型
我的答案：读：list::const_iterator
写：list::iterator
标准答案：同上

9.2 对于接受一个容器创建其拷贝的构造函数，和接受两个迭代器创建拷贝的构造函数，解释它们的不同
我的答案：一个通过对容器对象的拷贝构建，一个通过迭代器指针构建
标准答案：

9.3 如果将以下使用insert返回值将元素添加到list中的循环程序改写为将元素插入到vector中，分析循环将如何工作
list lst;
auto iter = lst.begin();
while(cin>>word)
{
iter = lst.insert(iter,word);
}
改写后的容器逻辑效果一样，但性能差异巨大
vec内存连续：每次在头部insert，后面元素都要向后移动一位

9.4 假定iv是一个int的vector，下面程序存在什么错误，你将如何修改
vector::iterator iter = iv.begin(),mid = iv.begin() + iv.size()/2;
while(iter!=mid)
{
if(iter == some_val)
{
iv.insert(iter,2some_val);
}
}
修改：
1.接受insert返回值，刷新迭代器；插入成功后，迭代器要额外+1跳过新元素
2.不能提前缓存固定的mid，每一轮要重新计算中间位置
vector::iterator iter = iv.begin();
while(iter!=iv.begin() + iv.size()/2)
{
if(iter == some_val)
{
iter = iv.insert(iter,2some_val);
iter++;
}
iter++;
}

9.5 向下面语句这样调用insert是否合法？如果不合法，为什么？
iter = vi.insert(iter,*iter++);
不合法：在同一个表达式里对同一个迭代器既读又修改，没有规定的求值顺序
情况一：先执行iter++，再把自增后的iter传给insert，插入位置错乱
情况二：先拿iter作为插入位置，在执行iter++
标准没有强制顺序，结果不可预测-> 未定行为(崩溃/逻辑错误)

9.6 在本节对名册(roster)调用equal的例子中，如果两个容器中保存的都是C风格的字符串会发生什么？

1.equal默认使用==比较两个元素
2.对于char*，==比较的是内存地址，不是字符串里面的字符
哪怕两个字符串字面量内容一样，如果地址不同，char* == char*的结果是false
只有两个指针指向同一块内存才判定相等

9.7 本节提到过，标准库算法不会改变它们所操作的容器的大小。为什么使用back_inserter不会使这一断言失效

9.8 你认为算法不改变容器大小的原因
我的答案：算法通过调用迭代器来改变容器，而通过迭代器只能改变容器内元素的值，无法改变容器大小
